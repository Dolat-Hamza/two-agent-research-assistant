PASS: SSE framing is correct — event:\ndata:\n\n format, CRLF normalization in parser, correct headers including X-Accel-Buffering: no. Run lifecycle is correctly ordered: RUN_STARTED first, RUN_FINISHED last, TEXT_MESSAGE_* in START→CONTENT→END order.

5. CopilotKit / Vercel AI SDK Compatibility

Partial (improved)

CopilotKit (useCoAgent)

After fixes, the backend now emits correct field names. Remaining blockers before CopilotKit's HttpAgent can consume this backend:

STATE_DELTA: CopilotKit applies JSON Patches internally. We now emit STATE_SNAPSHOT which CopilotKit handles as a full replacement — this is acceptable but means no incremental patching. Full JSON Patch support would require tracking previous state and computing RFC 6902 diffs.
The "CopilotKit" pill in console-header.tsx is cosmetic — no CopilotKit SDK is in package.json. Once the backend is confirmed spec-compliant, useCoAgent can replace the custom use-agent-stream.ts hook entirely.

Vercel AI SDK (useChat)

Vercel AI SDK uses a different wire protocol (0:/1:/9: prefixed data lines) — fundamentally incompatible framing. Not a drop-in. Vercel deployment plumbing (Next.js config, same-origin proxy route) is correctly structured for Vercel hosting.

6. Critical Bugs

#1
RUN_STARTED / RUN_FINISHED missing thread_id
Spec requires {thread_id, run_id}. Backend only sent {run_id}. CopilotKit and other clients would reject or lose thread context.
Fixed
#2
STATE_DELTA payload was a snapshot object, not RFC 6902 JSON Patch
Spec: delta: List[Any] (JSON Patch). Backend sent {active_agent, step, tool_calls}. Renamed to STATE_SNAPSHOT with correct snapshot wrapper.
Fixed
#3
TEXT_MESSAGE_CONTENT used content instead of delta; missing message_id
Standard AG-UI consumers (CopilotKit, LangGraph UI) would render empty bubbles. Renamed to delta and message_id added to all three TEXT_MESSAGE events.
Fixed
#4
TOOL_CALL_START used tool_name / stuffed args in wrong event
Spec: tool_call_name in START; args in a separate TOOL_CALL_ARGS event with delta: string. Both fixed.
Fixed
#5
TOOL_CALL_END carried result instead of TOOL_CALL_RESULT
Spec: END carries only tool_call_id; result is a separate TOOL_CALL_RESULT event with {message_id, tool_call_id, content: string, role: "tool"}. Both events now correct.
Fixed
#6
Non-spec ERROR event; early return without RUN_FINISHED
Backend emitted ERROR and returned early, leaving spec-conformant consumers hanging. Now emits RUN_ERROR (terminal event per spec; no RUN_FINISHED needed after it). LLM errors raised to correct handler instead of leaking into message content.
Fixed
#7
Agent card: capabilities.streaming: false was wrong; missing card fields; wrong canonical path
Fixed: streaming: true, added defaultInputModes/defaultOutputModes, tags[] on skills, both /.well-known/agent.json and /agent-card.json now served.
Fixed
#8
A2A request/response shape is not JSON-RPC 2.0
Planner sends plain {task_id, skill, query}. Spec: JSON-RPC 2.0 with method: "message/send" and params.message.parts[]. Requires architectural rewrite using a2a-sdk.
Open
#9
MCP server on deprecated SSE transport
transport="sse" deprecated in MCP 1.7+. Switch to transport="http" (Streamable HTTP). Client URL /sse → /mcp. Also: new Client per request should be a long-lived singleton.
Open
#10
web_search returns hardcoded mock results
All queries return example.com URLs. README implies real search. Integrate Tavily, Brave, or Serper to deliver on the "research assistant" premise.
Open

8. Verdict & Production Roadmap

PROTOTYPE-ONLY. Excellent visual demo and well-engineered frontend. Protocol fidelity to AG-UI is substantially improved by this audit (7 blockers fixed). A2A and MCP remain non-conformant and require architectural investment.

Top 5 tasks before production

1
Use ag_ui.core Pydantic models as the serialization source
Serialize all events with .model_dump_json(by_alias=True) to guarantee schema compliance and make future spec upgrades automatic.
AG-UI fidelity

Rewrite planner → search as JSON-RPC 2.0 A2A

A2A interop

Replace custom SSE hook with useCoAgent
